🏗️ CargoVision AI - Technical ArchitectureThis document outlines the system design, data flow, and component interaction of the CargoVision AI platform.1. High-Level System OverviewCargoVision AI is built on a Decoupled Client-Server Architecture. The frontend handles user interaction and image visualization, while the backend manages the computationally heavy AI inference and risk assessment.2. Component Breakdown🎨 Frontend (React.js)State Management: Handles the lifecycle of an upload (Idle → Uploading → Processing → Result).Canvas Rendering: Uses OpenCV-like logic or CSS overlays to map coordinates from the API onto the UI to highlight suspicious objects.Real-time Feedback: Displays a "Risk Meter" based on the severity of detected items.⚙️ Backend (FastAPI)REST API: Provides endpoints for image ingestion and health checks.Preprocessing: Resizes and normalizes incoming X-ray images to the $640 \times 640$ input size required by the model.Post-processing: Converts raw model outputs (tensors) into human-readable JSON (labels, confidence scores, and bounding boxes).🧠 AI Engine (YOLOv8)Model: YOLOv8 (Ultralytics) trained on the Sixray dataset.Task: Object Detection (Localization + Classification).Classes: Detects items such as knives, guns, batteries, and liquid containers.3. Data Flow (The Request Cycle)Input: User selects an X-ray image (.jpg, .png).Transport: Image is sent as a Multipart/Form-Data POST request to /predict.Inference:FastAPI reads the file into an ndarray.The YOLOv8 model performs a forward pass:$$\hat{y} = f(x, \theta)$$Where $x$ is the input image and $\theta$ represents the trained weights.Risk Logic: The system iterates through detections. If a "High Risk" object (e.g., Gun) is found with confidence $> 0.8$, the global Risk Score is set to "Critical."Output: JSON response sent back to React:JSON{
  "status": "success",
  "detections": [
    {"label": "Knife", "confidence": 0.92, "bbox": [120, 45, 200, 300]},
  ],
  "risk_score": 85,
  "recommendation": "Manual Inspection Required"
}
4. Security & PerformanceConcurrency: FastAPI uses uvicorn with workers to handle multiple simultaneous scan requests.Resource Management: Model is loaded into memory once at startup (not per request) to minimize latency.
